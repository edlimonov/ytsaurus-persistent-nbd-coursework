# КТ-2. Воспроизводимая демонстрация

**Статус:** инструкция для будущего прогона. На 24.11.2026 команды из этого файла не выполнялись на доступном преподавателю стенде. Заполнять результат только после запуска на зафиксированном SHA.

## Предусловия

Нужны публичный форк YTsaurus с перенесённым кодом, Linux-стенд с controller agent, exec node, Porto и NBD, тестовый YT-кластер, права на создание и монтирование динамической таблицы, `yt`, `nbd-client`, `mkfs.ext4` и доступный `/dev/nbd0`. Один `device_id` использует только одна активная джоба. Перед началом записать SHA форка, конфигурацию стенда, версию образов и адрес тестового кластера в приватный протокол без токенов.

Примеры ниже используют таблицу `//tmp/nbd_course_demo`, имя task `nbd_course_demo`, cookie `0`, том `work`, размер `1073741824` и блок `4096`. Если путь таблицы меняется, поправить оба [примера](../../examples/) до запуска. Нужен незанятый путь таблицы: подготовка форматирует устройство и уничтожит прежнюю файловую систему с тем же `device_id`.

## Подготовка тестового устройства, один раз

В корне checkout **той же версии кода**, которая развёрнута на стенде:

```bash
ya make yt/yt/experiments/public/dynamic_table_nbd_server -r
./yt/yt/experiments/public/dynamic_table_nbd_server/prepare_dynamic_table_nbd_devices.sh \
  --yes-format \
  --table-path //tmp/nbd_course_demo \
  --task-name nbd_course_demo \
  --job-count 1 \
  --volume-id work \
  --size 1073741824
```

Скрипт сам создаёт/монтирует таблицу при необходимости, подключает временный NBD export, вызывает `mkfs.ext4` и отключает устройство. Повторять этот шаг для проверки сохранности **нельзя**.

## Положительный и отрицательный запросы

В корне учебного пакета, после завершения подготовки и проверки настроенного `yt` CLI:

```bash
yt vanilla --spec "$(cat examples/01-persistent-volume.yson)"
yt vanilla --spec "$(cat examples/01-persistent-volume.yson)"
yt vanilla --spec "$(cat examples/02-invalid-mount.yson)"
```

Первая операция должна показать RW mount `/slot/sandbox/work` и записать строку в `marker.txt`. Вторая отправляется только после полного завершения первой; её stdout должен показать старую строку **до** добавления новой. Третья должна завершиться ошибкой валидации `mount_path` до старта джобы. Простой `yt vanilla` не заменяет проверку stdout/stderr и статуса в API операции.

После демо не удалять таблицу по шаблону или по имени из документа. Удаление возможно только после проверки конкретного пути, владельца, тестового назначения и отсутствия активных пользователей.

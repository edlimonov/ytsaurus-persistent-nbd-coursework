# КТ-2. Стратегия проверок

**Владелец:** Наиль Зарипов. **Дата:** 24.11.2026. **Статус:** план. Текущие ручные пробы не засчитываются как автоматический CI или опубликованная приёмка.

## Уровни

1. **Unit:** валидация YSON-конфига и геометрии, выбор стабильного device ID, кеш/flush и обработка пустых блоков; фиксация старого data-node NBD поведения.
2. **Интеграция:** controller agent с тестовой динамической таблицей и правами; exec node + NBD server + Porto на Linux; два независимых устройства и повторный запуск.
3. **Сквозные сценарии:** AT-001–AT-013 в доступном преподавателю стенде, с отдельными журналами по operation/job ID, SHA и версией образов. Негативные случаи проверяют, что джоба не стартует и format не выполняется.
4. **НФТ:** 20 последовательных циклов, измерение p95 подготовки, размер кеша и восстановление после отказа. Не смешивать результаты холодного и прогретого кеша.

## Базовый воспроизводимый прогон КТ-2

* Зафиксировать SHA публичного форка, образа/сборки, версии Linux/Porto/NBD и параметры таблицы.
* Поднять доступный стенд из чистого checkout по инструкции YTsaurus; создать таблицу строгой схемы и один раз отформатировать тестовое устройство. Подготовку производить только с тестовыми `device_id`.
* Отправить `01-persistent-volume.yson`: проверить mount и запись. После завершения отправить ту же спеку и проверить старый marker.
* Отправить `02-invalid-mount.yson`: зафиксировать ранний отказ и отсутствие джобы.
* Сохранить вывод команд, статус операции, отчёт CI и факт/дату прогона; заполнить трассируемость.

Нужны тестовая схема/seed и безопасный cleanup. Удаление таблицы после теста выполняется только для явно созданной учебной таблицы; команда cleanup документируется с защитой от удаления чужого пути. `--yes-format` нельзя запускать второй раз на устройстве с данными.

## CI и CD

Для КТ-2 PR/MR pipeline должен на том же SHA выполнять формат/линтер, сборку изменённых C++ целей, применимые unit/integration-тесты и поиск секретов. Проверка намеренного падения теста/линтера — отдельный запуск. План CD на КТ-3: неизменяемый образ по digest, тестовый стенд, smoke и сохранённый предыдущий digest для отката. В текущем учебном пакете pipeline **не запущен**; конкретная конфигурация зависит от выбранного репозитория и доступного runner.

## Критерии доказательства

Каждый отчёт содержит SHA, дату, исполнителя, стенд/версии, команды, входные данные, ожидаемый и фактический результат, PASS/FAIL/BLOCKED, ссылку на лог. Скриншот без команды и SHA недостаточен. Обязательные пороги на КТ-3: ≥70% собственного прикладного кода и ≥80% бизнес-логики; для монорепозитория YTsaurus нужно заранее согласовать границы «собственного кода» и корректный способ расчёта.

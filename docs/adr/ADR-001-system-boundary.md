# ADR-001. Реализовать функцию внутри YTsaurus

**Владелец:** Наиль Зарипов. **Дата:** 24.11.2026. **Статус:** предложено; сверить с upstream review. **Связи:** US-001/002/003, NFR-002/003/007, D-01/D-02.

## Контекст

Спека операции проходит через controller agent, а файловая система джобы создаётся на exec node и показывается job proxy. Функция должна проверять права до запуска, поддерживать жизненный цикл NBD и не менять семантику обычных джоб.

## Альтернативы

1. **Встроить в YTsaurus.** Использовать существующие конфиг, job proto, volume manager и Porto. Плюс — единый жизненный цикл и ACL. Минус — более широкий C++ diff и дорогостоящий стенд.
2. Отдельный сервис, который модифицирует спеки и монтирует диски. Плюс — независимый релиз. Минус — дублирование валидации, отдельные права и невозможность безопасно управлять внутренним workspace джобы без изменений YTsaurus.
3. Скрипт внутри пользовательской джобы. Плюс — малый объём серверного кода. Минус — привилегии mount внутри джобы и отсутствие ранней проверки/учёта жизненного цикла.

## Решение

Реализовать интерфейс томов в серверных компонентах YTsaurus. Внешним интерфейсом остаётся YT API с YSON-спекой операции; отдельный REST-сервис не создаётся. По подтверждению автора, преподаватель засчитывает YTsaurus и стенд как сервисную часть. Учебные документы хранятся отдельно рядом с checkout; код публичного PR будет в форке YTsaurus.

## Последствия и пересмотр

Нужны регрессионные тесты обычных джоб и корневого NBD, сборка нескольких C++ компонентов и доступный проверяющему стенд. Решение пересматривается, если upstream уже предоставляет эквивалентную форму volume/mount или требует иной публичный API. PR должен быть минимальным и отделять persistent dynamic-table сценарий от датанодового расширения.

# КТ-2. Контракт пользовательской спеки

**Владелец:** Наиль Зарипов. **Версия:** 24.11.2026, проектный контракт по внутренней ветке `vk-25.3-nbd@c983b610de7`. **Статус:** согласование с актуальным upstream до публичного PR. **Интерфейс:** YT API `start_operation` для vanilla; тело операции — YSON. JSON-совместимый фрагмент описан в [nbd-task.schema.json](../../api/nbd-task.schema.json), но код YTsaurus остаётся источником истины.

## Вход

На уровне одной vanilla task:

| Поле | Тип | Правило |
| --- | --- | --- |
| `disk_request.disk_space` | int64, байты | Положительный запрос на локальный sandbox; в режиме path-mounted томов `disk_request.nbd_disk` отсутствует |
| `nbd_volumes` | map `volume_id → volume` | Один или несколько именованных томов; для MVP каждый том имеет `disk_space` и `nbd_disk.dynamic_table` |
| `nbd_volumes[id].disk_space` | int64, байты | `1..512 GiB`; должен совпадать с размером подготовленного NBD-устройства |
| `nbd_volumes[id].nbd_disk.dynamic_table.table_path` | YT path | Путь к смонтированной динамической таблице строгой схемы `(device_id, block_id, block_payload)` |
| `block_size` | int64, байты | Положительное; должно совпадать с геометрией устройства, в примере 4096 |
| `max_cached_block_count`, `read_batch_size`, `write_batch_size` | int64 | Положительные; дефолты кода 1024, 16, 16 |
| `nbd_mounts[]` | список `{volume_id, mount_path}` | Каждый том упомянут ровно один раз; путь канонический и строго внутри `/slot/sandbox/`; пути не пересекаются друг с другом и с tmpfs |

YSON-путь операции сохраняет существующие поля (`command`, `job_count`, `pool`, ресурсы). Новые поля необязательны для обычной джобы; приведённая JSON Schema описывает только фрагмент **при использовании** path-mounted томов, а не всю операцию. Поле `restrict_porto_place` было временной особенностью конкретного внутреннего стенда и не включено в публичный контракт без отдельного обоснования.

## Идентификатор, доступ и состояние

Текущий прототип строит строку устройства как `task_name/job_cookie/volume_id`, затем переводит её в `device_id` таблицы. Один и тот же том при последовательном повторном запуске должен использовать ту же строку и геометрию. Права на чтение колонок и запись таблицы проверяются от имени пользователя операции; токен передаётся инфраструктурой YTsaurus и не помещается в пример спеки. Устройство должно быть отформатировано до первого запуска; серверная джоба не форматирует его автоматически.

## Выход и ошибки

При успехе YT возвращает operation ID, а внутри джобы `findmnt -T <mount_path>` показывает RW NBD/ext4. Это не отдельный REST endpoint: статус и ошибки доступны через штатный API операции/джобы. Негативные ответы содержат контекст поля или `table_path`, но не содержимое блоков и не секреты. Стабильные числовые коды ошибок для новой функции пока не определены; это требуется согласовать перед публикацией контракта.

| Случай | Ожидаемая стадия и результат |
| --- | --- |
| `mount_path=/tmp/x`, `..`, пересечение mount/tmpfs | Валидация спеки отклоняет операцию до job start |
| Неизвестный либо повторный `volume_id` | Валидация спеки отклоняет операцию до job start |
| Нет read/write, таблица не mounted или неверной схемы | Инициализация controller agent отклоняет операцию |
| Размер/block_size не совпадает с подготовленным устройством | Подготовка NBD завершает джобу ошибкой, данные не форматируются |
| Таблица или сеть пропала во время I/O | I/O/джоба получают ошибку; автоматическое восстановление не обещано |

**Повторы:** повторный запуск операции разрешён только после завершения предыдущей джобы с тем же `device_id`. Одновременная запись двумя джобами в одну ext4 за пределами MVP и не защищена текущим кодом. Версионирование публичной формы спеки — через ревью upstream и тесты совместимости; спецификация будет обновлена вместе с PR.

## Примеры и вызов

Положительная демонстрационная спека: [01-persistent-volume.yson](../../examples/01-persistent-volume.yson). Отрицательная: [02-invalid-mount.yson](../../examples/02-invalid-mount.yson). Команда запуска при наличии доступного тестового кластера и предварительно подготовленной таблицы:

```bash
yt vanilla --spec "$(cat examples/01-persistent-volume.yson)"
```

Для второй проверки запустить ту же спеку только **после окончания** первой операции: новый вывод `cat /slot/sandbox/work/marker.txt` должен содержать старую строку. Конкретное время/состояние/operation ID заносятся в протокол, а не подставляются в документацию заранее.
